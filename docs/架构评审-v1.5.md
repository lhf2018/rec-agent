# 主动推荐 Agent 架构评审（v1.5）

评审对象：技术方案 v1.4 + 架构图。结论已落实到 `技术方案.md` v1.5。

---

## 第一部分：总体评价

**是否具备主动推荐 Agent 的基本架构？**  
**基本具备骨架，但「主动性」仍偏弱。** 当前更像「事件触发 → 资格放行 → 引擎出候选 →（可选）Agent 决策 → 校验交付」。资格检查回答的是「能不能推」，尚未完整回答「值不值得推」。Agent 与引擎、校验的边界是清楚的，这是正确方向。

**最大的三个优点**

1. **计算与决策分离**：引擎封闭候选 + Agent 白名单工具，避免「大模型包一层就叫推荐 Agent」。
2. **生成 ≠ 交付**：独立 Guard、条件降级、交付再验，硬约束不可被降级绕过。
3. **可验证意识**：结构化 Trace、引擎基线对照、三组指标（系统/质量/触达）方向正确。

**最大的五个问题**

1. **主动决策不完整**：缺「机会判断」（立即推 / 抑制 / 不推）；易变成每次曝光都尝试跑链路。
2. **路由条件不可执行**：DIRECT/REACT 多为例子，研发无法写成确定性 if；有「为用 Agent 而用 Agent」风险。
3. **Agent 增量价值未钉死**：未强制规定「Agent 必须改变选择或提供引擎模板无法给出的证据理由」，易退化成文案层。
4. **用户状态语义偏薄**：长短期冲突、反馈含义、过期与可信度规则不够可编码；有过度修正风险。
5. **第一版略重**：资格/交付/路由/预算/三层 Guard/实验同时铺开，空仓库落地时易拖慢；逻辑要保留，代码可合并。

**当前最大风险**  
**验证机制与业务策略并列第一，略重于「runtime 架构不足」。** Runtime 骨架够用；若先写代码却没有「何时不调模型」「如何证明 Agent 增益」的硬约定，容易做出一个贵、慢、说不清价值的系统。

**若只能改三处（已纳入 v1.5）**

1. 增加 **机会判断（Opportunity）**：与资格分离；默认抑制优于盲目推荐。  
2. 写成 **可编码的路由表** + **Agent 增益验收定义**。  
3. 冻结 **MVP 用户状态模型** 与 **三臂离线评测（引擎 / DIRECT / REACT）**。

## 第二部分：问题清单与优先级

| 优先级 | 当前问题 | 为什么重要 | 建议改法 | 第一版是否必须 |
| --- | --- | --- | --- | --- |
| P0 | 「能不能推」与「值不值得推」混在资格里或缺失 | 主动推荐的核心；否则每次触发都烧成本且打扰 | 拆 Eligibility 与 Opportunity；结果含 recommend_now / suppress / skip | 是 |
| P0 | 路由条件不可落地 | 无法稳定控制是否进 ReAct | 用缺口类型+冲突标志+预算的确定性表 | 是 |
| P0 | 未定义 Agent「无效调用」 | 可能只写漂亮理由 | 评测要求：改选择或证据理由相对模板有增量；否则算失败用例 | 是 |
| P0 | 硬约束绕过面（补召回/降级/交付）需写死测试 | 安全底线 | MVP 必测：补召回再过滤、降级再校验、拒绝不可降级绕过 | 是 |
| P1 | 长短期偏好冲突规则不清 | 推荐错位、体验差 | 硬约束永久优先；短期信号只偏置软排序；单次行为不改长期 | 是 |
| P1 | 多样性职责分散 | 引擎与 Guard 可能重复或漏洞 | 引擎做粗多样；Guard 做最终名单硬裁剪 | 是 |
| P1 | 无三臂对照评测设计 | 证伪不了 Agent | 离线固定用例跑 Engine / DIRECT / REACT | 是 |
| P1 | 模块物理拆分过细 | 空项目落地慢 | 逻辑分层保留，代码可合并为 policy/engine/runtime/api | 建议 |
| P2 | delay / wait_new_signal 时机状态 | 更细主动策略 | 第一版用 suppress+下次触发即可 | 否 |
| P2 | 多渠道统一触达台 | 超范围 | 站内展示即可 | 否 |
| P2 | 在线学习 / 复杂记忆 | 过早 | 快照只读；画像更新独立、离线 | 否 |
| P2 | 预期收益模型打分 | 缺数据 | 机会判断用规则代理，收益模型待实验 | 否 |

## 第三部分：优化后的整体架构（要点）

见技术方案 v1.5 第 2 章与架构图。逻辑阶段：

1. 场景信号与任务创建（幂等）  
2. **资格 Eligibility**（能不能）  
3. **机会 Opportunity**（值不值得 · 新增）  
4. 用户状态快照（只读）  
5. 引擎召回/过滤/排序 + 基线缓存  
6. 路由 DIRECT / REACT / FALLBACK / SKIP  
7. Agent 受控决策  
8. 独立校验与仲裁  
9. 交付前治理  
10. 展示、反馈、Trace、离线评测与（后续）实验  

**合并说明：** 代码上 `eligibility`+`opportunity`+`delivery` 可同属 `policy/`；`budget` 可并入 `loop`；不必微服务。
